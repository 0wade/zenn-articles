## はじめに

「HTTP」という言葉はよく耳にするかもしれませんが、HTTPはそれ単体で動いているわけではありません。HTTPの下には **TCP/IP** という通信の土台があり、その上に HTTP が乗っかる形で動いています。

この記事では、TCP/IP の仕組みをレイヤー（層）の概念から丁寧に説明し、「3ウェイハンドシェイク」「ポート番号」「IPアドレス」といった重要な概念を一つひとつ解説していきます。

---

## TCP/IP とは何か

**TCP/IP（Transmission Control Protocol / Internet Protocol）** は、インターネット上でデータをやりとりするための通信規約（プロトコル）の集まりです。

「TCP」と「IP」は別々のプロトコルですが、常にセットで使われるため「TCP/IP」とまとめて呼ばれます。

- **IP**：データをどこに届けるかを決める（住所の役割）
- **TCP**：データを確実・正確に届ける（配送方法の役割）

---

## ネットワークの「レイヤー（層）」という考え方

ネットワーク通信は、複数の役割を **層（レイヤー）** に分けて設計されています。これを **レイヤーモデル** と呼びます。

レイヤーに分ける理由は、**それぞれの役割を独立させることで、変更や拡張をしやすくする**ためです。たとえば HTTP を HTTPS に切り替えても、TCP/IP 層は変わらずそのまま使えます。

### TCP/IP モデル（4層構造）

| 層番号 | 層の名前 | 役割 | 代表的なプロトコル |
|--------|----------|------|-------------------|
| 第4層 | **アプリケーション層** | アプリ間のやりとり | HTTP, HTTPS, DNS, FTP |
| 第3層 | **トランスポート層** | 信頼性のある通信 | **TCP**, UDP |
| 第2層 | **インターネット層** | ネットワーク間の経路制御 | **IP**, ICMP |
| 第1層 | **ネットワークインターフェース層** | 物理的なデータ転送 | Ethernet, Wi-Fi |

```
ブラウザがリクエストを送る流れ（下に向かって包んでいく）

┌─────────────────────────────┐
│  アプリケーション層         │  "GET /index.html HTTP/1.1"
├─────────────────────────────┤
│  トランスポート層（TCP）    │  ポート番号を付ける
├─────────────────────────────┤
│  インターネット層（IP）     │  送信元・宛先IPアドレスを付ける
├─────────────────────────────┤
│  ネットワークインターフェース層 │  電気信号・電波に変換して送信
└─────────────────────────────┘
```

上の層から下の層へ、データに情報を「包んで（カプセル化して）」送り、受信側は逆に「開封」しながら上の層へ渡していきます。

---

## IP（インターネットプロトコル）とは

IP は「データをどこへ届けるか」を担当するプロトコルです。

### IPアドレス

IPアドレスは、ネットワーク上の機器を識別するための **住所** です。

```
IPv4アドレスの例：
192.168.1.10

0〜255 の数字4つをドットで区切った形式（32ビット）
```

- **グローバルIPアドレス**：インターネット上で一意（ユニーク）なアドレス。自宅のルーターやサーバーに割り当てられる。
- **プライベートIPアドレス**：社内LAN・家庭内ネットワークで使うアドレス（`192.168.x.x` など）。インターネット上では使えない。

### IP 通信の特徴（ベストエフォート）

IP 単体では「届けようとする」だけで、**届いたかどうかを確認しません**。これを「ベストエフォート（best effort）」と言います。

パケット（データの小さなかたまり）が途中で失われても、IP は気にしません。その信頼性を補うのが、次に説明する TCP の役割です。

---

## TCP（トランスミッションコントロールプロトコル）とは

TCP は「データを確実・正確に届ける」ことを担うプロトコルです。

### TCP の主な特徴

| 特徴 | 説明 |
|------|------|
| **コネクション確立** | 通信前に相手と接続を確立する（3ウェイハンドシェイク） |
| **順序保証** | バラバラに届いたパケットを正しい順序に並び替える |
| **再送制御** | 届かなかったパケットを再送する |
| **フロー制御** | 送信速度を相手の処理能力に合わせて調整する |

---

## 3ウェイハンドシェイク

TCP 通信では、実際にデータを送り始める前に **3回のやりとりで接続を確立**します。これを **3ウェイハンドシェイク（Three-way Handshake）** と呼びます。

```
クライアント（例：ブラウザ）          サーバー（例：Webサーバー）
        │                                        │
        │ ──── ① SYN ────────────────────────> │  「接続したいです」
        │                                        │
        │ <─── ② SYN-ACK ─────────────────────  │  「わかりました、私も準備OKです」
        │                                        │
        │ ──── ③ ACK ────────────────────────> │  「了解しました。通信を始めます」
        │                                        │
        │         ＜ここからデータ送受信＞         │
```

| ステップ | 送るもの | 意味 |
|----------|----------|------|
| ① | **SYN**（Synchronize） | 「接続要求」。通信したいことを伝える |
| ② | **SYN-ACK**（Synchronize-Acknowledge） | 「接続了解 + 私も接続要求」。双方向の確認 |
| ③ | **ACK**（Acknowledge） | 「了解」。これで接続が完了する |

### なぜ3回なのか？

2回では足りない理由があります。

- 1回目（SYN）：クライアント → サーバーへの「送信できる」ことを確認
- 2回目（SYN-ACK）：サーバー → クライアントへの「受信・送信できる」ことを確認
- 3回目（ACK）：クライアント → サーバーへの「受信できる」ことを確認

この3回を経て、**双方向の通信路が確立された**ことを互いに確認できます。

### 切断時：4ウェイハンドシェイク

接続を切断するときは、4回のやりとりが必要です（どちら側からも終了を宣言できるため）。

```
クライアント                              サーバー
        │ ──── FIN ──────────────────> │  「送信を終了します」
        │ <─── ACK ───────────────────  │  「了解しました」
        │ <─── FIN ───────────────────  │  「私も送信を終了します」
        │ ──── ACK ──────────────────> │  「了解しました」
        │                                        │
        │        ＜接続が完全に閉じる＞           │
```

## ポート番号とは

IPアドレスで「どのコンピュータか」を特定できますが、そのコンピュータ上には複数のアプリが動いています。**どのアプリへデータを届けるか**を区別するのが **ポート番号** です。

> **アナロジー**：IPアドレスはマンションの住所、ポート番号は部屋番号のようなものです。

### ウェルノウンポート（よく知られたポート番号）

| ポート番号 | プロトコル | 用途 |
|-----------|-----------|------|
| 80 | HTTP | 通常の Web 通信 |
| 443 | HTTPS | 暗号化された Web 通信 |
| 22 | SSH | リモートログイン |
| 21 | FTP | ファイル転送 |
| 25 | SMTP | メール送信 |
| 53 | DNS | ドメイン名解決 |
| 3306 | MySQL | データベース接続 |

ポート番号は **0〜65535** の範囲で指定できます。

- **0〜1023**：ウェルノウンポート（有名なサービス用に予約済み）
- **1024〜49151**：登録済みポート（特定のアプリが使用）
- **49152〜65535**：動的・プライベートポート（一時的な通信に使用）

### 実際の通信では

```
https://example.com へのアクセス

送信元：192.168.1.10:54321（ブラウザが一時的に使うポート）
宛先  ：93.184.216.34:443（HTTPS なのでポート443）
```

ブラウザはリクエストのたびに送信元ポートを動的に割り当て、サーバー側はウェルノウンポートで待ち受けます。

## TCP と UDP の違い

トランスポート層には TCP 以外に **UDP（User Datagram Protocol）** もあります。

| 項目 | TCP | UDP |
|------|-----|-----|
| 接続確立 | 必要（3ウェイハンドシェイク） | 不要 |
| 信頼性 | 高い（再送あり） | 低い（再送なし） |
| 速度 | 遅め | 速い |
| 用途 | Web通信・ファイル転送・メール | 動画ストリーミング・DNS・オンラインゲーム |

**UDP は「速さ優先」**のプロトコルです。多少データが欠けても問題ないリアルタイム通信（ビデオ通話など）に向いています。

---

## HTTP と TCP/IP の関係をまとめると

```
ブラウザで https://example.com を開くときに起きていること

① DNS でドメイン → IPアドレス に変換（UDP / ポート53）
② TCP 3ウェイハンドシェイクで接続確立（TLS ハンドシェイクも加わる）
③ HTTP リクエスト送信（アプリケーション層）
        ↓ TCP がパケットに分割・順序管理
        ↓ IP が宛先・送信元アドレスを付与
        ↓ 物理ネットワーク経由で届く
④ サーバーからレスポンスが返ってくる（逆の手順）
⑤ ブラウザがHTML を受信・レンダリング
```

HTTP は「何を送るか（内容）」を決めるだけで、「どうやって確実に届けるか」は TCP に任せています。

---

## まとめ

- **TCP/IP** はインターネット通信の基盤となる2つのプロトコルの組み合わせ
- **IP** はパケットの宛先を決める住所の役割を担い、信頼性は保証しない
- **TCP** は接続確立・順序保証・再送制御を行い、信頼性の高い通信を実現する
- **3ウェイハンドシェイク**（SYN → SYN-ACK → ACK）で通信前に接続を確立する
- **ポート番号** でコンピュータ上のどのアプリへ届けるかを区別する
- HTTP は TCP/IP の上に乗っかって動いており、TCP が「確実に届ける」仕事を担っている
- **UDP** は信頼性より速度を優先するプロトコルで、動画や DNS などで使われる
